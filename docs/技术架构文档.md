# 充电桩小程序 - 技术架构文档

## 1. 项目概述

### 1.1 项目简介
充电桩小程序是一个前后端分离的微服务架构系统，旨在为用户提供便捷的充电桩查询、预约、支付等服务。

### 1.2 核心目标
- 🎯 为新能源车主提供实时充电桩信息查询
- 🎯 支持在线预约和充电服务
- 🎯 完整的支付和订单管理系统
- 🎯 后台管理系统支持

```
  - sys_permission (权限表)
```

```
  - 充电桩位置查询（地图）
  - 充电桩实时状态
  - 充电桩故障报修

数据库表:
  - charging_pile (充电桩表)
  - charging_pile_detail (充电桩详情)
```

```
功能模块:

  - 订单查询统计
  - 订单取消
  - 订单评价

数据库表:
  - charging_order (订单表)
  - order_detail (订单详情)
```

#### 4.1.4 支付服务 (Payment Service)
```
功能模块:
  - 支付流程管理
  - 支付渠道集成 (微信支付/支付宝)
```

```
功能模块:
  - 文件上传/下载
  - 短信通知
  - 邮件通知

  - 日志管理
```

### 4.2 服务间通信

```
同步调用: OpenFeign + Ribbon (负载均衡)
```

## 5. 权限认证体系

### 5.1 认证流程

```
客户端请求
    ↓
用户输入用户名密码
    ↓
认证服务验证
    ↓
生成JWT Token
    ↓
Redis存储Token & Session
    ↓
返回Token给客户端
    ↓
客户端请求时携带Token
    ↓
网关/拦截器验证Token
    ↓
从Redis获取权限信息
    ↓
验证权限
    ↓
执行业务逻辑 or 返回无权限
```

### 5.2 Redis中的存储结构

```
Key: user:token:{userId}
Value: JWT Token

Key: user:session:{sessionId}
Value: {
  "userId": 123,
  "username": "user@example.com",
  "roles": ["admin", "user"],
  "permissions": ["system:add", "system:edit"],
  "loginTime": "2024-05-26 10:00:00"
}

Key: user:permissions:{userId}
Value: [
  "charging:view",
  "charging:order:create",
  "order:view",
  "payment:view"
]

Key: role:permissions:{roleId}
Value: [权限列表]
```

### 5.3 权限设计

```
权限层级:
  - 系统权限 (system:*)
  - 充电桩权限 (charging:*)
  - 订单权限 (order:*)
  - 支付权限 (payment:*)
  - 用户权限 (user:*)

角色定义:
  - 超级管理员 (admin)
  - 平台运营 (operator)
  - 充电桩管理员 (pile-admin)
  - 普通用户 (user)
  - 商家 (merchant)
```

## 6. 数据库设计

### 6.1 核心数据表结构

#### 6.1.1 用户表 (sys_user)
```sql
CREATE TABLE sys_user (
  user_id BIGINT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(64) UNIQUE NOT NULL,
  password VARCHAR(255) NOT NULL,
  real_name VARCHAR(64),
  phone VARCHAR(20),
  email VARCHAR(128),
  avatar_url VARCHAR(255),
  status TINYINT DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at TIMESTAMP NULL,
  INDEX idx_username (username),
  INDEX idx_phone (phone)
);
```

#### 6.1.2 充电桩表 (charging_pile)
```sql
CREATE TABLE charging_pile (
  pile_id BIGINT PRIMARY KEY AUTO_INCREMENT,
  pile_name VARCHAR(128) NOT NULL,
  pile_number VARCHAR(64) UNIQUE NOT NULL,
  location_name VARCHAR(255),
  latitude DECIMAL(10, 8),
  longitude DECIMAL(11, 8),
  total_slots INT DEFAULT 1,
  available_slots INT DEFAULT 0,
  power_type ENUM('AC', 'DC', 'AC_DC'),
  voltage INT,
  current_capacity INT,
  status TINYINT DEFAULT 1,
  operator_id BIGINT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_location (latitude, longitude),
  INDEX idx_status (status),
  FOREIGN KEY (operator_id) REFERENCES sys_user(user_id)
);
```

#### 6.1.3 订单表 (charging_order)
```sql
CREATE TABLE charging_order (
  order_id BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_number VARCHAR(64) UNIQUE NOT NULL,
  user_id BIGINT NOT NULL,
  pile_id BIGINT NOT NULL,
  start_time DATETIME,
  end_time DATETIME,
  duration_minutes INT,
  power_consumed DECIMAL(10, 2),
  total_amount DECIMAL(10, 2),
  status TINYINT DEFAULT 0,
  remark VARCHAR(500),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_pile_id (pile_id),
  INDEX idx_created_at (created_at),
  FOREIGN KEY (user_id) REFERENCES sys_user(user_id),
  FOREIGN KEY (pile_id) REFERENCES charging_pile(pile_id)
);
```

#### 6.1.4 支付记录表 (payment_record)
```sql
CREATE TABLE payment_record (
  payment_id BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  amount DECIMAL(10, 2) NOT NULL,
  payment_method ENUM('WECHAT', 'ALIPAY', 'BANK_CARD'),
  transaction_id VARCHAR(128) UNIQUE,
  status TINYINT DEFAULT 0,
  paid_at TIMESTAMP NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_order_id (order_id),
  INDEX idx_user_id (user_id),
  INDEX idx_status (status),
  FOREIGN KEY (order_id) REFERENCES charging_order(order_id),
  FOREIGN KEY (user_id) REFERENCES sys_user(user_id)
);
```

### 6.2 数据库设计原则
- ✅ 使用自增主键
- ✅ 关键字段建立索引
- ✅ 使用外键保证数据一致性
- ✅ 添加时间戳字段（created_at, updated_at）
- ✅ 逻辑删除而非物理删除
- ✅ 大字段单独表存储

## 7. Nacos配置中心

### 7.1 配置管理策略

```
配置命名规范:
namespace: 生产环境 (prod) / 测试环境 (test) / 开发环境 (dev)
group: 微服务名称
dataId: {application}-{environment}.properties

例如:
user-service-prod.properties
charging-service-test.properties
payment-service-dev.properties
```

### 7.2 典型配置示例

#### application.yml (通用配置)
```yaml
spring:
  application:
    name: user-service
  cloud:
    nacos:
      discovery:
        server-addr: nacos-server:8848
        namespace: prod
      config:
        server-addr: nacos-server:8848
        file-extension: yaml
        namespace: prod

server:
  port: 8081
  servlet:
    context-path: /api/user
```

#### user-service-prod.yaml (业务配置)
```yaml
user:
  tokenExpireTime: 86400
  tokenPrefix: "Bearer "
  
redis:
  host: redis-server
  port: 6379
  password: ${redis.password}
  timeout: 3000
  maxRetries: 3

database:
  url: jdbc:mysql://mysql-server:3306/charging_db
  username: ${db.username}
  password: ${db.password}
  pool-size: 20
```

## 9. 开发流程

### 9.1 本地开发环境搭建

```bash
# 1. 启动基础设施
docker-compose -f docker/docker-compose.yaml up -d

# 2. 等待服务启动
sleep 30

# 3. 初始化数据库
mysql -h localhost -u root -p < backend/user-service/src/main/resources/db/schema.sql

# 4. 启动Nacos并配置
# 访问 http://localhost:8848/nacos
# 导入配置文件 config/nacos-config/

# 5. 启动后端服务
cd backend
mvn clean install

# 6. 启动前端开发服务
cd frontend/charging-admin
npm install
npm run dev
```

### 9.2 微服务启动顺序

```
1. Nacos 注册中心 & 配置中心
2. MySQL 数据库
3. Redis 缓存
4. 基础服务 (Common Service)
5. 核心服务 (User → Charging → Order → Payment)
6. API Gateway (可选)
7. 前端应用
```

## 12. 性能优化

### 12.1 缓存策略

```
一级缓存: Redis (热点数据)
  - 用户信息缓存 (user:info:{userId})
  - 充电桩列表缓存 (charging:piles:{area})
  - 权限缓存 (user:permissions:{userId})
  
缓存时间:
  - 用户信息: 1小时
  - 充电桩: 30分钟
  - 权限: 2小时
  
缓存预热: 启动时加载
缓存更新: 主动更新 + TTL过期
```

### 12.2 数据库优化

```
- 合理建立索引
- 避免全表扫描
- 使用连接池
- SQL语句优化
- 考虑读写分离
- 定期统计分析
```

### 12.3 服务优化

```
- 异步处理非核心业务
- 消息队列解耦
- 服务限流降级
- 断路器保护
- 超时控制
```

```
日志级别:

  - 操作类型
  - 操作结果
  - 耗时
```

### 13.2 监控指标

## 16. 常见问题

### Q1: 如何实现分布式事务?
A: 使用Seata框架实现分布式事务管理，或使用消息队列+补偿机制。

### Q2: 如何处理服务间的调用超时?
A: 配置合理的超时时间，使用断路器、重试、降级等策略。

### Q3: 如何扩展新的微服务?
A: 新建服务模块 → 继承common依赖 → 配置Nacos → 自动注册发现。

### Q4: 小程序如何处理登录?
A: 使用wx.login获取code → 后端验证code → 返回JWT Token → 小程序存储Token进行后续请求。

### Q5: 如何处理充电桩的实时数据更新?
A: 使用WebSocket推送，或轮询接口，数据存储在Redis中。
